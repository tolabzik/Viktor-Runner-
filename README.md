# VIKTOR RUNNER — Office Chaos 2.0

Бесконечный офисный экшен-платформер в браузере. Герой — Виктор с предоставленной фотографии. Без CDN, регистрации и сторонних игровых сервисов.

## Запуск через Docker Compose

На сервере должны быть установлены Git, Docker Engine и плагин Docker Compose.

```bash
git clone https://github.com/tolabzik/Viktor-Runner-.git
cd Viktor-Runner-
cp .env.example .env
docker compose up -d --build
```

Откройте `http://IP_СЕРВЕРА:8080` (на самом сервере — `http://localhost:8080`). Порт меняется через `PORT` в `.env`. Для доступа извне разрешите выбранный порт в межсетевом экране.

```bash
docker compose ps
docker compose logs --tail=100 game
curl -f http://127.0.0.1:8080/api/health
```

Один контейнер: Gunicorn + Python WSGI API + статические файлы. SQLite и ключ сессий хранятся в постоянном именованном томе `records`. Контейнер работает непривилегированным пользователем, корневая файловая система доступна только для чтения. Внешняя БД не нужна.

**Обычный перезапуск и пересборка сохраняют рекорды. `docker compose down -v` удаляет том и рекорды — не используйте эту команду для обновления.**

Обновление:

```bash
git pull --ff-only
docker compose up -d --build
```

**Шабашка** — конверт: +500 очков и 30 патронов к автомату. **Премия** — зелёный портфель: +1000 очков, рост на 20 секунд, дополнительный выдерживаемый удар и разрушение коробок. Кофе даёт неуязвимость на 8 секунд; фиолетовый бейдж уменьшает героя. Мокрый пол не замедляет под действием кофе.

24 случайные офисные шутки, вывески по дороге, пять меняющихся зон, четыре вида оружия, монеты, прыжки на противников, движущиеся платформы, пружины и бесконечная генерация.

## Доска почёта

Перед стартом вводится ник. По завершении онлайн-забега результат автоматически отправляется на сервер. В таблице: топ-20, собственное место даже за пределами топа, периоды за всё время / последние 7 дней / последние 24 часа. На игрока отображается один лучший забег в выбранном периоде.

`Очки = метры + монеты × 25 + противники × 100 + шабашки × 500 + премии × 1000`.

Итог пересчитывает сервер. Проверяются типы, правдоподобие статистики, принадлежность и время забега. Повторная отправка не создаёт дубликат. Это базовая защита, **не полноценный античит**: симуляция остаётся в браузере.

Игрок определяется подписанной cookie, а не ником или аккаунтом. Очистка cookie, другой браузер или устройство создают нового игрока. Одинаковые ники допускаются. Личный рекорд дополнительно хранится локально. При недоступности API можно играть локально, но такой забег не попадёт в общий рейтинг. Неотправленный результат можно повторно сохранить кнопкой до ухода с экрана результатов. Срок сохранения онлайн-забега — 24 часа, допустимая игровая длительность — до 2 часов.

## Управление

Виктор бежит сам. Пробел / W / ↑ — прыжок, удержание меняет высоту. X / J / мышь — стрельба. 1–4 или Q — оружие. A / D или ← / → — скорость. S / ↓ — присесть. P / Escape — пауза, M — звук. На телефоне есть одновременные сенсорные кнопки.

## HTTPS и обратный прокси

Для публикации через HTTPS укажите в `.env`:

```dotenv
BIND_ADDRESS=127.0.0.1
PORT=8080
COOKIE_SECURE=1
APP_ORIGIN=https://runner.example.org
```

Проксируйте сайт и `/api/` вместе на `http://127.0.0.1:8080`, сохраняя заголовок `Host`. Не включайте кеширование API. Если прокси находится в другом контейнере, используйте общую Docker-сеть и адрес `game:8080`, а не loopback прокси-контейнера. `COOKIE_SECURE=1` нельзя использовать при обычном HTTP: браузер не отправит cookie.

Приложение не доверяет входящему `X-Forwarded-For`. За прокси встроенные лимиты общие на его адрес; дополнительное ограничение по клиентам настройте на прокси. Для небольшого офисного сервера используется один процесс Gunicorn с восемью потоками.

## Резервное копирование

```bash
mkdir -p backups
docker compose exec -T game python tools/backup.py > "backups/records-$(date +%F-%H%M%S).tar.gz"
```

Архив содержит согласованный снимок SQLite и `.session-key`. Не копируйте работающий WAL-файл базы обычным `cp`. Храните архив вне сервера и не публикуйте: он содержит ключ сессий.

Для восстановления остановите `game`, сохраните текущий том отдельной резервной копией, замените в томе базу и ключ файлами из доверенного архива, удалите оставшиеся файлы `leaderboard.sqlite3-wal` и `leaderboard.sqlite3-shm` только при остановленном приложении, восстановите владельца UID/GID 10001 и запустите сервис. Не подменяйте файлы работающей базы.

## Разработка и проверки

```bash
python -m unittest discover -s tests -p 'test_*.py' -v
for f in public/*.js; do node --check "$f"; done
PORT=8765 python app.py
```

Локальный `app.py` слушает только 127.0.0.1 и предназначен для разработки. В Docker используется Gunicorn. Для браузерных тестов отдельно нужны Playwright и Chromium:

```bash
python tests/browser_smoke.py
python tests/mechanics.py
```

Тестовый интерфейс игры доступен только на `127.0.0.1` с `?test=1`. Описание проверок и ограничений — `docs/TESTING.md`. GitHub Actions запускает API-тесты, проверяет синтаксис JavaScript и собирает/запускает Docker Compose. Состояние конкретного запуска смотрите во вкладке Actions.

Основные файлы: `public/game.js` — игровой движок; `office.js` — персонажи и события; `online.js` — рейтинг; `assets.js` — слои героя; `app.py` — сервер; `compose.yaml` — деплой. Фотография предоставлена пользователем; перед публичным распространением убедитесь в согласии изображённого человека.
